5e. Visual Grid (Table / Seat Matrix): CSS Grid auto-fill. Cell 64x64px, rounded `var(--radius-md)`, status colored. Hover scales up (1.05) with tooltip popover. Click free cell -> action; click occupied cell -> order profile.
5f. Kanban Board: Horizontal scrollable columns container. Column header with status badge + count. Cards stacked vertically inside `--bg-card` with left border matching status color.
5g. Wizard / Stepper: Left panel vertical step list 01-05. Right panel current step form. Top progress bar 0-100%. Footer Back (ghost) | Next (primary).

5k. Inline Editable Cell Pattern: Click text to replace with input field (`--border-focus` ring). Save on Blur/Enter, Cancel on Escape. Small spinner when saving.

CRITICAL ARCHITECTURE REQUIREMENTS:
- ZERO BACKEND / DATABASE: No Node.js, Express, MongoDB, or external database APIs.
- LOCALSTORAGE PERSISTENCE: All data MUST be persisted client-side using browser `localStorage`.
- PWA & OFFLINE-FIRST: Progressive Web App with Service Worker setup to work smoothly offline.
- CROSS-TAB REAL-TIME SYNC: Use native browser `window.addEventListener('storage', ...)` or custom React Hooks so changes in one tab (e.g., Waiter App or Customer QR) immediately reflect in another tab (e.g., Kitchen KDS or Cashier POS) in sub-seconds without page reloads.

1. PROBLEM STATEMENT & BUSINESS GOALS
-------------------------------------------------------------------------------
1. Billing Quantity & Item Errors: Eliminates human error where items are billed incorrectly or running orders (KOT 1 + KOT 2) are omitted.
2. Kitchen Miscommunication & Delay: Replaces paper slips with real-time digital KDS screens split by stations (Main Kitchen, Drinks Bar, Bakery KDS), complete with prep timers, Web Audio alerts, and void order alerts.
3. Theft & Audit Leakage: Prevents staff from cancelling bills or deleting items silently without audit logs.
4. Inventory Wastage: Auto-deducts recipe raw materials upon billing and alerts on low/expired stock.

2. STRICT ROLE-BASED ACCESS CONTROL (RBAC) & AUTHENTICATION FLOW
-------------------------------------------------------------------------------
The application strictly enforces Role-Based Access Control (RBAC). Instead of exposing all operating views on a single shared screen, users MUST be authenticated and routed to their respective ISOLATED DASHBOARDS based on their assigned role:

1. ADMIN DASHBOARD (`/admin`): Master control for Restaurant Owner/Manager.
2. CUSTOMER DASHBOARD (`/customer`): Public dashboard for Customers (Advance booking, pre-order dishes, track live status & loyalty).
3. CASHIER POS DASHBOARD (`/billing`): Terminal for Cashier / Billing Manager.
4. WAITER CAPTAIN DASHBOARD (`/waiter`): Terminal for Waiters / Floor Captains.
5. KITCHEN KDS DASHBOARD (`/kitchen`): Terminal for Kitchen Staff & Chefs.

-------------------------------------------------------------------------------
2.1 PUBLIC SIGNUP VS ADMIN STAFF CREDENTIALS GENERATION
-------------------------------------------------------------------------------
A. PUBLIC SELF-REGISTRATION (SIGNUP ALLOWED ONLY FOR 2 ROLES):
   1. CUSTOMER: Can register an account via public signup form (`/auth/customer-signup`) using Name, Phone, Email, Password. Enables advance table reservations, pre-booking food dishes, tracking loyalty points, and viewing order history.
   2. ADMIN (RESTAURANT OWNER): Can register the restaurant branch and master admin account via `/auth/admin-signup`.

B. STAFF CREATION & CREDENTIAL GENERATION (STRICTLY ADMIN-ONLY — NO PUBLIC STAFF SIGNUP):
   1. Cashiers, Waiters, and Kitchen Staff CANNOT self-register on the platform.
   2. The Admin Dashboard includes a dedicated "Staff Management & Credential Generator" panel (`src/components/Admin/AdminStaffCredentialsPanel.tsx`).
   3. Admin enters Staff Name, Phone, Role (`CASHIER` | `WAITER` | `KITCHEN`), and generates/assigns a unique System ID/Username & Password.
   4. Staff members log in at `/auth/login` using the exact ID and Password generated by the Admin.
   5. Admin can activate/deactivate staff accounts or reset passwords at any time.

-------------------------------------------------------------------------------
2.2 ADMIN REVENUE DASHBOARD & DYNAMIC DATE FILTERING

The Admin Revenue Dashboard MUST feature interactive analytics charts (ApexCharts) with flexible time-range filtering:
